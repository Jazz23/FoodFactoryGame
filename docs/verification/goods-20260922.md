## What the listen-server test demonstrates

`GoodsListenServerTests.HostAndRemoteUseRpcForGrantTransferRejectionAndUnobservedTime`, in Editor PlayMode:

- One `NetworkManager` starts a Tugboat server plus its local (host) client; a second `NetworkManager` connects as a remote client over loopback UDP on an OS-assigned port. FishNet logged `Remote connection started for Id 0` and `Id 1` — two distinct server-side connections.
- The test bootstraps a committed goods save in a unique OS-temp directory, spawns `GoodsNetworkBridge` from the isolated fixture prefab, and calls `InitializeServer` with a connection→player resolver (host → granted player, remote → ungranted player).
- **Unobserved-site progression:** with no subscription and no site presentation, the server clock spoils the test lot both in memory and in the committed snapshot; no baseline was sent.
- **Granted baseline:** the host subscribes and receives a site-filtered baseline.
- **Unauthorized remote:** the remote's subscription is refused (`subscription-forbidden`) and its transfer RPC returns `forbidden`.
- **Authorized transfer:** the host's transfer RPC is accepted; the committed snapshot preserves total quantity (10) and the kitchen holds the moved 2.
- Cleanup (in `finally` and `[TearDown]`) stops connections, destroys fixture objects, restores the prefab's non-spawnable flag, and deletes the temp directory; a post-run check found no leftover `FoodFactoryGoodsListen` data.

## Environment notes

- The first async PlayMode attempts never entered Play mode: the active `SampleScene` was dirty (a temporary GameObject created and destroyed while authoring the fixture prefab), and the Test Runner's save-scene precondition blocked it. Saving produced **no file diff**, and the next run started.

The entry was removed through the collection API and the prefab is authored `_isSpawnable: 0`, so the generator skips it. The test enables spawning in memory only.
