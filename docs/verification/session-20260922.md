## Issues found and fixed during verification

1. **Menu and readout never rendered** in the first build. The `UIDocument` had no PanelSettings: an earlier authoring run did not serialize the reference. The script now writes `m_PanelSettings` through `SerializedObject`, and an authoring assertion guards it; that assertion was shown failing on the broken scene before the fix. A clean re-run of the script serialized the reference. Why the earlier run left it null was not fully determined.
2. **Rejected clients didn't learn why over real UDP.** The first player-build run showed the client disconnected with `RemoteConnectionClose` and never processed the reply, while the in-process test passed. FishNet force-closes about 100 ms after a failed authentication. The client now disconnects itself after reading a rejection, and the server kicks only after a 2 s grace.
3. **A rejected duplicate renamed the connected player**, because `RegisterOrResolve` ran before the duplicate check. Admission now checks the connected identity with a read-only lookup before any write.
4. **Unreadable text fields**: white text was inherited by the light theme's inputs. Only labels are white now.

## Not verified / remaining

- Movement and orbit **input** were not driven in the player build; the captures show the default orbit view. Movement is replicated by FishNet's `NetworkTransform`, but no test moves an avatar and checks the remote pose.
- No separate-machine (LAN) run, firewall configuration, or headless `-batchmode -server` player run. Server-only mode is covered only in Editor PlayMode.
- The 8-player cap (`server-full`) and `server-not-ready` paths have no automated test.
