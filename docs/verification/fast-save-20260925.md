# Verification: held-connection fast save (2026-09-25)

`GoodsSnapshotStore` now caches only a row it successfully committed through a held connection and compares all four
stored fields (revision, world ID, payload and checksum) under `BEGIN IMMEDIATE` before skipping previous-snapshot
validation. A changed head uses the existing validation/quarantine path. Release and failed commits discard the cache.
Only `Assets/Scripts/Goods/GoodsSnapshotStore.cs` changed for this implementation. All test databases used isolated OS
temp paths; no application database or migration was touched.

Unity 6000.5.9f1 recompiled after the final edit with no compilation errors. The first compile exposed a local
definite-assignment error; it was corrected before any test run. The Editor console showed zero errors after the final tests.
