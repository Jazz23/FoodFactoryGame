Two-process playtest, development player `build_33da8693eac0` (before the change), host save on E: (Seagate ST2000DM001
hard disk). The host stuttered about once a second; the guest did not. Host log:
`[Goods] commits=522 avg=250.6ms max=1087.5ms payload=14.2KB`.

| E: hard disk | 324.6 ms | 310.9 | 385.9 | 768.6 |
| C: SSD | 4.7 ms | 4.5 | 5.0 | 12.7 |

## Tests

| Run | Filter | Matched | Result |
| --- | --- | --- | --- |
| Live Editor `run_tests` editor, async | none (all EditMode) | 132 | 132 passed (includes 4 new `HeldSaveTests`) |
| Live Editor `run_tests` playmode, async, first attempt | none (all PlayMode) | 14 | 2 passed, 12 failed in TearDown only (`world.db` still open) |
| Live Editor `run_tests` playmode, async, after `SessionRoot.ReleaseServer` releases the save | none (all PlayMode) | 14 | 13 passed, 1 failed |
| `run_tests` playmode, change stashed (baseline) | `HotbarKeysOverAStackAndDropsOnTheHotbarAssignSlots` | 1 | 1 failed, same message |

The first PlayMode attempt showed that FishNet does not run the bridge's `OnStopServer` within `SessionRoot.Shutdown`, so
the session teardown deleted a folder whose save was still held; `ReleaseServer` now releases it. The remaining failure,
`HotbarKeysOverAStackAndDropsOnTheHotbarAssignSlots` ("The pointer is over the dough stack"), fails identically on the
unmodified code (baseline row) and is the intermittent test noted in [supplier-20260924](supplier-20260924.md); not caused
by this change. The Pipeline runner returned results synchronously with no native XML artifact path.

New coverage (`HeldSaveTests`): saves use WAL; a held save commits every tick, is readable by another connection while held,
and leaves no `-wal` file after release; a held save recovers after a refused (stale) commit; `Hold` needs an existing
database and `Release` ignores unheld or null paths.
