# Architecture Map

## Runtime Ownership

- `GameSceneManager` adapts FishNet scene callbacks and portal/elevator requests to the transition service.
- `PlayerInventory` owns the local player's persisted 80-slot inventory, Tab-opened grid UI, and 10-slot hotbar; every inventory slot is ordinary storage, while persistent hotbar shortcuts refer to item types and expose the selected item/count for gameplay consumers.
- `CameraFollow` follows the local player and applies a scene grid's default orthographic zoom only when entering that grid; `CameraZoom` owns scroll-wheel zoom for the bootstrap camera and ignores scroll while the inventory or expanded build/test tools cards have pointer focus.
- `GameSceneManager` resets OutsideTest load and reconciliation state at each server start/stop so disabled Enter Play Mode reload options cannot retain stale scene topology.
- `FloorTransitionCoordinator` owns transition phases, sequence validation, pending floor loads, loaded-floor reuse, return-floor state, and unload guards.
- `NAIStateManager` owns the authoritative factory snapshot, simulation, and runtime persistence coordination.
- `FactoryWorldState` owns building, floor, entity, connection, route, and truck records.
- `FactoryBuildingEditService` owns validated topology edits, deterministic equipment relocation, and endpoint rebinding.
- `FactoryBuildingEditService.TryCreateTopologyPlan` compares compact authored records with one selected schema-9 save; plans contain `Create`, `Update`, or destructive `Delete` operations plus authored/database fingerprints. `TryApplyTopologyPlan` applies the exact confirmed plan or rejects it as stale.
- `FactoryBuildingTopologyResolver` owns authored-versus-persisted source selection and conflict comparison; saved topology remains authoritative once loaded.
- `FactoryBuildingLayoutAsset` stores compact authored building topology (identity, footprint, stories, and doors); generated shell children remain rebuildable output.
- `TestBuildingCreator` and `GameSceneManager` consume the compact layout when it is assigned; `BuildingShellAssembler` is the deterministic geometry adapter and reports rebuild success separately from whether geometry changed.
- `FactoryWorldSqliteStore` is the persistence adapter. Database roles are application save, authoring data, test fixture, and temporary preview.
- `TestBuildingCreatorEditor` mutates the compact asset first and reconciles generated preview shells by stable building ID. Successful topology edits immediately apply the changed building to an explicit full-path database target through the fingerprinted, atomic topology service; immediate edits use the direct database path and avoid creating a duplicate preview plan. Preview, inspector selection, repaint, undo/redo, and generated-shell refresh remain read-only; whole-building deletion and clear operations require destructive confirmation and are blocked when the target is active in Play Mode.
- The default `factory-world.db` is project-local while running in the Unity Editor and uses `Application.persistentDataPath` in production. The project-local database is development state and is not source-controlled.
- `NAIStateManager` clears its static configured database-path override at `SubsystemRegistration`, so explicit temporary paths set by test fixtures cannot leak into a later Play session when domain reload is disabled. A fixture may still configure its isolated path after startup.
- `FactoryWorldSqliteStore.Inspect`, `PlanMigration`, `ApplyMigration`, `Read`, and `Save` keep schema inspection, migration, loading, and writing explicit.
- `OutsideTestFloorPresentation` and related views render explicit building/floor state; they are not authoritative state owners.
- `OutsideTestFloorDebugPanel` is a UI client of the current player/floor binding and should not be used as the primary API for domain tests.
- `VisualRegressionEvidence` owns deterministic Building 13 SceneView capture, ROI comparison, and evidence-packet metadata. It is editor-only verification infrastructure; it does not author gameplay geometry or decide independent visual review.
- `BuildingShellAssembler` marks only the topmost story roof for filled-top presentation; intermediate story roofs retain their side geometry without an exterior top surface so they cannot project through upper-story walls.
- `Virtual3DSize` uses the player's transform origin as the stable bottom-pivot foot anchor on the legacy 2D path and the 3D controller's X/Z foot anchor after production ownership. A shallow horizontal capsule extends upward from that anchor with independent world-space width and ground depth (player prefab: 0.6 × 0.3); animation bounds never move the collider. Transitions, interior containment, and depth sorting consume that same logical anchor.
- `SceneGrid.CellSize` scales world-space presentation only. `IndoorGrid`, `InsideFactoryVisuals`, and factory entity views continue to use saved logical cell coordinates and configured building sizes.
- `SceneGrid` optionally exposes authored logical construction bounds. `FactoryConstructionService` validates every shell footprint cell against those bounds before mutation; unset bounds preserve fixture flexibility.
- `IndoorGrid` owns the generated interior test-line presentation and its `FactoryBuild/ToggleTestLines` Input System action; hiding the lines only deactivates their derived renderers and does not affect the boundary collider.
- `IndoorGrid.SetAllTestLinesVisible` applies the Test Tools toggle to every loaded floor and carries the chosen visibility into subsequently loaded interiors.
- `TestToolsShell` owns the Test Tools and expanded Build Tools runtime controls; `FactoryBuildController` owns equipment selection, elevator connection previews, and expanded-build right-click removal.
- `FactoryElevatorTransfer` pairs persisted elevator-bottom/top entities by building, adjacent floor indices, and matching logical cell. It moves elevator input buffers to the paired floor's output buffer so existing adjacent conveyor handoffs carry items onward in either direction.
- `FactorySpatialAdapter` maps stable logical factory locations to either the existing 2D projection or 3D XZ coordinates; floor elevation is presentation-only and is never persisted.
- `FactoryConstructionService` is the pure construction boundary for deterministic 3D previews and commits. It validates shell footprint cells, wall-cell overlap, default entrances, interior-only sizing, equipment/conveyor occupancy, and paired elevator cells before calling `FactoryWorldState` mutation APIs. `Factory3DConstructionController` owns only Input System action-map clones, selection, ray-to-logical-cell snapping, preview coloring, and cancel state; it never persists or owns occupancy. Its mutually exclusive modes are `Idle`, `BuildingPlacement`, `EquipmentPlacement`, `MovingSelection`, and `RemovalConfirmation`; removal selection creates a fresh target-specific confirmation and only confirmation reaches the destructive commit path. Pointer-focused UI input is blocked, the construction camera is explicit, and `FactoryBuildController` yields ordinary 2D build input while an active 3D mode owns the scene.
- `GameSceneManager` and `NAIStateManager` bridge runtime construction to the existing authority. Building creation/removal, entity placement/move/removal, endpoint preservation, destructive confirmation, save dirtiness, broadcasts, and disposable 3D proxy reconciliation all remain on the existing state/persistence seam. The controller's story elevation comes from the active `TestBuildingCreator.WallHeight` through `GameSceneManager.OutsideTestStoryHeight`, with a 3-unit fallback matching the established presentation default.
- `Factory3DPrototypeController` owns the reversible `Factory3DPrototype` scene slice: fixed camera, primitive floor/equipment views, adapter-based picking, discrete elevator floor cycling, and an isolated save/load smoke fixture. `Factory3DPrototypePlayer` exercises the same reusable `Factory3DTraversalController` used by the production player.
- `Factory3DTraversalController` owns production XZ traversal after local network ownership is established by `GameSceneManager`. It consumes cloned Input System `Player/Move`, `Player/Interact`, and `UI/Cancel` actions, uses a bottom-anchored `CharacterController` in the prototype or a disposable child capsule collider in production, and exposes the same `FactorySpatialAdapter` foot anchor for interaction. Explicit 3D ownership disables the legacy `Movement`/`Rigidbody2D` simulation; releasing ownership restores the 2D compatibility path. It never loads scenes, saves state, or persists floor elevation.
- `Factory3DPresentationBridge` is the runtime 3D presentation owner. After `NAIStateManager` and the OutsideTest `SceneGrid` are ready, it rebuilds the disposable 3D shell from authoritative records, gates legacy `SpriteRenderer`, `TilemapRenderer`, 2D collider, and 2D body components with captured enabled/simulated state, creates disposable capsule visuals for 3D traversal players, and configures the enabled gameplay camera even when that camera lives in Bootstrap. Authority or scene loss clears generated objects and restores the captured compatibility state; screen-space UI is never gated.
- `PlayerSceneTransition`, `ScenePortal`, and `InsideFactoryElevator` expose 3D foot-anchor request/query overloads. They forward transition requests to `GameSceneManager` and leave `FloorTransitionCoordinator` sequence, duplicate-request, arrival, and failure handling authoritative. UI focus, active build placement, and transition state gate 3D input; merely having build tools available does not stop traversal.
- `Factory3DTraversalCollisionPresenter` is a disposable interior collision-only presenter for floor, walls, and equipment. `Factory3DOutsideTestCollisionPresenter` is its authoritative OutsideTest topology counterpart, deriving world-floor, shell-wall, door-opening, and equipment colliders while keeping render proxy colliders absent. `GameSceneManager` owns both runtime presenters; `Player.prefab` contains the production traversal controller and child capsule authored through Unity's prefab API.
- `Factory3DOutsideTestProxyAssembler` derives disposable 3D OutsideTest blockouts from authoritative `BuildingRecord` and `OutsideTestFloorRecord` data. It reuses `BuildingShellValidation`, `TestBuildingCreator` wall placements/spans, `BuildingCoordinates`, and `FactorySpatialAdapter`; proxy hierarchy names are stable logical building/floor identities, not persisted proxy identities. Building-level doors are presented on floor 0, matching the existing record model and 2D shell semantics. The `FactoryWorldState` overload and the narrow `NAIStateManager.TryGetOutsideTestBuildingInteriorSemantics` seam carry explicit interior-only classification plus `FactoryWorldState.GetInteriorSize` output so interior-only equipment is not shell-inset; a missing ID is rejected rather than defaulted.
- `Factory3DOutsideTestProxyAssembler` adds a derived inset roof only to the top story. It also derives a disposable ground plane and logical grid from configured `SceneGrid` bounds without adding colliders. `Factory3DOutsideTestProxyView.SetActiveFloor` provides a reversible inspection mode that isolates one floor, restores its slab, and hides that floor's roof to avoid presentation occlusion; clearing the mode restores the full shell.
- `Factory3DOutsideTestProxyView` owns only the transient proxy root and forwards reconciliation to the assembler. It never writes `FactoryWorldState`, save records, authored layout, shell objects, 3D coordinates, elevation, or proxy state. Generated ground, grid, slab, and roof meshes are reused when geometry is unchanged and explicitly released when disposable proxy nodes are removed. In Play Mode the editor companion renders only from an initialized `NAIStateManager`; an absent or not-ready runtime authority clears the proxy instead of falling back to authored records, while editor preview remains authored-record based. The companion observes `EditorApplication.playModeStateChanged` and `EditorApplication.update`; the update callback validates creator, grid, active-scene, and proxy-root identity before its authority no-churn fast path, so invalidation cleanup does not depend on a Scene View repaint. Both callbacks are removed on disable/destroy.
- `Factory3DRouteSnapshotBuilder` derives immutable source/belt/elevator/storage route data, queue occupants, floor coordinates, orientation, storage capacity, source production, and discrete elevator phases from `FactoryWorldState`. `NAIStateManager.BuildRoutePresentationSnapshot` is the read-only runtime façade; snapshots contain no Unity object references and are never persisted.
- `Factory3DRouteProxyAssembler` and `Factory3DRouteProxyView` reconcile disposable route primitives by canonical building/floor/entity IDs. They filter by active floor, clear on authority loss, remove stale nodes, and leave simulation and save state untouched. `Factory3DRouteSelectionController` uses the existing Input System point action for read-only hover/selection and connected-route highlighting; it never issues placement, routing, production, or inventory mutations.
- `Factory3DRouteAuthorityPresenter` is the runtime lifecycle bridge. It runs after simulation updates, builds route snapshots only from an initialized `NAIStateManager`, observes the existing OutsideTest floor-selection event/current-floor binding, and clears the dedicated child route root when authority, grid, or scene identity is unavailable. `Factory3DOutsideTestProxyView` preserves that child root while shell proxies reconcile, so repeated reloads cannot duplicate or stale the route presentation.
- `Factory3DInteriorPresenter` is the bounded runtime interior lifecycle bridge. `GameSceneManager` creates one per loaded interior scene without scene/prefab authoring. It reads an initialized `NAIStateManager` route snapshot, the active floor owned by `InsideFactoryController`, and the loaded interior `SceneGrid`/`IndoorGrid`; it clears its disposable root when any required authority, scene, or grid identity is invalid and uses a fingerprint guard to reconcile only changed presentation data.
- `Factory3DInteriorProxyAssembler` and `Factory3DInteriorProxyView` render disposable floor slabs, perimeter walls, and active-floor entity markers with stable building/floor/entity keys. They reuse matching objects, remove stale proxies, retain hidden floors in authority data, and never write simulation or persistence state. Story elevation uses `BuildingCoordinates` and positions use `FactorySpatialAdapter` with the default story height of 3.
- `Factory3DRouteFixture` is a deterministic two-floor Source → Belt → Elevator → Belt → Storage fixture with fixed IDs and a temp-path-only save helper. It is test infrastructure and cannot target the application database.
- `Factory3DRouteVisualEvidenceTests` writes isolated snapshot JSON, proxy identity hierarchy JSON, camera PNGs, simulation ticks, and save-path records for source/elevator entry, transfer, storage arrival, floor hiding/reselection, and save/reload restoration under `TestResults/Factory3DRoute/<run-id>`.
- `PlayerInventory` grants one elevator top and bottom as starter equipment when each item is missing, and the hotbar selects those parts through the existing build controller.
- `FactoryTruckMarkerView` owns truck marker presentation, including switching a marker to a wireframe cube when its projected footprint is behind a configured building occlusion surface.

## 3D Production Contract

- Logical cell `(x, y)` is projected by `SceneGrid` from `logicalOrigin` through its configured projection and `cellSize` for the 2D path. `FactorySpatialAdapter.LogicalToWorld3D` intentionally uses the same origins and cell size as an orthogonal X/Z ground basis, independent of the 2D Dimetric shear; its inverse returns logical factory coordinates, so Unity transforms remain derived presentation state.
- Floor elevation is `BuildingCoordinates.GetFloorElevation(floorIndex, storyHeight)`. A floor index is never serialized as a Unity Y coordinate; the configured creator wall height supplies the OutsideTest story height and the shared interior presenter uses its explicit story-height setting.
- The player transform origin is the bottom/foot anchor. Factory shell slabs and equipment are positioned from logical cell corners/centers; wall and door geometry starts at the floor elevation; disposable capsule visuals are centered above the foot anchor. Building, route, and entity identities are stable logical IDs, not generated object instance IDs.
- Runtime collision is 3D-only while the bridge is active: OutsideTest and interior collision presenters derive floors, walls, door openings, and equipment from authoritative records. Generated render proxies do not carry colliders. The bridge preserves the legacy 2D path as a reversible compatibility layer until final parity acceptance.
- The gameplay camera is a bridge-owned symmetric dimetric orthographic camera while 3D presentation is active: yaw 45 degrees, downward elevation 30 degrees, and orthographic size `SceneGrid.OrthographicSize * SceneGrid.CellSize * sqrt(0.5)`. This makes the orthogonal X/Z ground basis project to the existing 2D diamond slopes and scale while retaining visible Y extrusion. It targets the local 3D foot anchor and restores its original transform/projection and `CameraFollow` state when ownership ends. Runtime 3D materials use the URP Lit shader when available, with the existing Standard fallback.
- Persisted state remains logical: building topology, floor/entity records, connections, routes, production buffers, and stable identities are saved exactly as before. World transforms, floor elevations, generated proxy nodes, materials, and camera state are presentation-only.

## Identity Rules

- Building and floor identities are stable gameplay data, not scene-object instance IDs.
- Large Unity identifiers in command output must be serialized as strings.
- Shell buildings include wall cells; usable interior size is `max(footprint - (2, 2), zero)`.
- Interior-only buildings retain their configured dimensions.
- Reconciliation and test teardown must preserve recoverable equipment and must not silently delete state.
- The 3D proxy applies the shell-to-interior one-cell translation only while presenting equipment; it does not rewrite equipment records or create a second occupancy authority.
- Construction previews are disposable data. A cancel or invalid preview leaves records, stable IDs, connections, routes, gameplay buffers, and proxy authority unchanged. Whole-building removal requires the same explicit destructive confirmation enforced by the domain service; NavMesh, free camera, and arbitrary rotation remain deferred.

## Change Boundaries

- Keep authored building intent compact and reproducible; do not hand-edit generated scene YAML when live Editor commands can apply the change.
- Extract bounded application services before introducing new assembly boundaries.
- Keep database inspection, migration planning, migration application, and saving as distinct operations.
- Saved topology has runtime precedence over authored shell dimensions. Authoring deletion removes the authored record and generated shell, then removes that building and its dependent state from the selected database after destructive confirmation; other saves retain their buildings. Creator IDs use a persisted high-water mark and are not recycled after deletion.

## Visual Verification Ownership

- Building 13 is the authored record with stable ID 13 in `OutsideTestBuildingLayout.asset`; generated shell children remain derived output.
- `VisualRegressionEvidence` writes only under `TestResults/VisualRegression/Building13` and never mutates scene or prefab YAML.
- A baseline manifest is the source of truth for camera, resolution, culling, view flags, and ROI. The after capture restores that manifest before rendering so the two images are comparable.
- Pixel comparison is scoped to the declared ROI and reports dimensions, differing pixels, maximum channel delta, tolerance, and artifact paths. A mismatch is a failed acceptance result, not a prompt to stack another code hypothesis.
- Renderer evidence is diagnostic only. Controlled isolation remains a manual, serialized step: disable one renderer/material/mesh group, capture, restore it, and record which isolated change removes the artifact.
- Evidence packets require an independent reviewer record (`pending`, `approved`, or `failed`) before a visual result can be considered accepted.
